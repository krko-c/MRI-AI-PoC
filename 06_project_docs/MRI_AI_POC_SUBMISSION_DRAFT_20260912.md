# MRI AI PoC 제출 초안

_작성: 2026-09-12 / 상태: 초안 — 구조 검증 완료, 실행 검증 미수행_
_웹 버전: https://claude.ai/code/artifact/8842556a-cb89-42b2-a1e8-2b26db1040b2_

사내 제출 서식 5개 칸에 옮겨 쓰기 위한 본문과 결과 자료 확보 방법.
수치 공란은 AIR Studio 실행 후 채운다.

## 서술 기조

주된 효과는 속도가 아니다. 현재는 이슈 선별과 조사 범위가 담당자의 착상과 가용 시간에 좌우되고,
조사 근거가 산출물에 남지 않는다. 이 시스템은 전건을 같은 기준으로 훑고, 조사 범위를 고정하며,
확인되지 않은 것을 "없음"이 아니라 "추가 확인사항"으로 남긴다.

시간 단축을 주효과로 내세우면 검수 공수 증가로 반박되므로
**누락 방지 · 근거 추적 · 재현성**을 전면에 둔다.

## 1. 업무 개선 효과

### 현행 업무 (AS-IS)

- MRI 1개 호에 주요 이슈 5~8건, 담당 2명이 처리
- 이슈 선별은 담당자가 원문을 읽고 아이디어가 연결되는 주제를 개별 판단으로 선정
- 조사는 인터넷 검색·타사 사례 확인 등 수작업이며, 가용 시간과 검색 결과에 따라 조사 깊이가 달라짐
- 이슈 1건당 대응안 초안까지 약 1일 소요, 한글문서로 작성
- 조사 근거의 출처가 산출물에 남지 않아 사후 확인과 재사용이 어려움

### 개선 후 (TO-BE)

- 호에 포함된 이슈 전건을 동일한 5개 관점(상품·투자테마·고객·채널·그룹협업)으로 스크리닝하고 선별 사유를 기록
- 선택 이슈는 5개 근거 영역(산업·고객 / 정책·제도 / 금융업권·경쟁사 / 자산운용·펀드시장 / 당사 현황)을
  고정 점검하고, 별도 탐색으로 사전에 예상하지 못한 신호까지 수집
- 모든 사실에 출처와 검증상태(확인 / 부분확인 / 추정 / 자료없음)를 부여
- 확인되지 않은 항목을 "없음"으로 단정하지 않고 추가 확인사항으로 분리
- 산출물이 기존 현황 / 계획 양식의 초안으로 즉시 생성되어 담당자가 검수·수정 후 사용

### 기대 효과

| 항목 | 현행 | 개선 후 |
|---|---|---|
| 이슈 검토 범위 | 눈에 띄는 주제 선택적 검토 | 호 내 전건 스크리닝 |
| 조사 범위 | 담당자 판단에 의존 | 5개 영역 고정 + 자동 확장 탐색 |
| 근거 추적 | 출처 미기재 | 사실 단위 출처·검증상태 기재 |
| 미확인 항목 | 조사 중단 시 누락 | 추가 확인사항으로 명시 |
| 산출물 형태 | 담당자가 처음부터 작성 | 현황/계획 양식 초안 자동 생성 |
| 재현성 | 담당자·시점별 편차 | 동일 기준·동일 절차 적용 |
| 1건 초안 소요 | 약 1일 | 시연 실행 시 측정 |

> 최종 제출물의 판단과 책임은 담당자에게 있으며 산출물은 검수를 전제로 한 초안이다.
> 소요시간 항목은 실제 측정치로 채우고, 측정 전에는 공란으로 둔다.

## 2. 운영 적용 가능성

### 현재 구현으로 즉시 적용 가능한 범위

- MRI 전건 스크리닝 및 검토 우선순위 제시
- 선택 이슈의 외부 조사 — 정책·제도, 뉴스·경쟁사, 공모펀드·ETF·펀드시장
- 조사 결과를 기존 현황 / 계획 양식의 대응안 초안으로 생성
- 담당자 검수 후 기존 절차대로 제출

### 추가로 필요한 사항

| 항목 | 내용 | 현재 상태 |
|---|---|---|
| 당사 내부자료 연계 | 과거 추진·중단 기획, 상품 파이프라인, 판매채널 전략 | 미연계 — 해당 항목은 자료없음 처리 |
| 펀드 상세지표 연계 | 개별 상품 설정액·성과 조회 | 미연계 — 상품 목록 수준까지 확보 |
| 부서 의견 반영 | 관련 부서 회신을 근거의 하나로 편입 | 미구현 |
| 다건 일괄 처리 | 선택한 2~3건을 연속 처리 | 현재 1건씩 처리 |
| 운영 절차 정의 | 검수 기준, 책임자, 산출물 보관·이력관리 | 정의 필요 |

### 운영 전제

- AI 산출물은 초안이며 최종 제출물은 담당자 검수 후 확정한다
- 선행조건이 있는 전략은 시스템이 단정하지 않고 검토 대상으로만 제시하며, 실행 판단은 사람이 한다
- 자료없음 항목은 담당자가 보완하거나 추가 확인사항으로 유지한다
- 지식베이스는 정기 갱신이 필요하다

| 검색 설계 | 계획과 실행 분리 · 소스별 전담 노드 · 의존 검색(상품 목록 조회 → 개별 상세 조회) · 사전 질문 외 확장 탐색 |
| 근거 관리 | 사실 단위 근거 ID 부여 · 검증상태 4단계 · 원문 핵심 주제 보존 여부 추적 |

### 환각·과장 방지 장치

생성형 AI의 대표적 위험을 업무 맥락에 맞춰 13종의 자동 반려 기준으로 규정하고
각 처리 단계에 규칙으로 내장했다.

- 근거 없는 수치·기관명·상품명·정책 생성 금지
- 자료없음을 "해당 없음"으로 단정 금지 — 검색 실패와 부재를 구분
- 정책 진행단계 상향 금지 — 논의·검토를 확정·시행으로 표현하지 않음
- 추정을 사실로 전환 금지 — 시기적 일치를 인과관계로 서술하지 않음
- 검증되지 않은 당사·그룹 역량을 보유 사실로 단정 금지
- 작성 단계에서의 신규 전략 창작 금지 — 앞 단계 결과에만 근거
- 상위 근거에 존재하는 정량정보의 임의 축약 금지

> 금융권 업무 적용 시 가장 중요한 평가 요소이므로, 기술 나열보다
> "무엇을 못 하게 막았는가"를 중심으로 서술한다.

### 테스트 결과 — 구조 검증 (완료)

- 워크플로 정의 파일 검증 — 구문 오류 0, 연결 누락 0 (스크리닝 9노드 / 조사 36노드)
- 처리 단계 간 데이터 계약 일치 검증 — 인계 필드 전 항목 일치 확인
- 단계별 출력 규격 중복 정의 해소 — 최종 산출물이 비어 생성되는 결함 사전 제거
- 두 워크플로의 식별자 충돌 제거 — 등록 시 상호 덮어쓰기 위험 해소
- 원문 핵심 주제가 최종 산출물까지 회수되는 경로 확보
- 제출 문서 변환 결과 OOXML 스키마 검증 통과

### 테스트 결과 — 기능 검증 (실행 후 기재)

- 등록 및 실행 정상 여부
- 지식베이스 실제 호출 여부
- 최종 산출물 양식 준수 및 원문 보존 여부
- 품질 기준 채점 결과 (합격선 80점 · 자동 반려 0건)

> 구조 검증만 완료된 상태임을 명시한다. 기능 검증 미완을 숨기면 시연 중 질문 하나로 무너진다.
> "설계·구조 검증 완료, 실행 검증 예정"은 PoC 단계로서 정상적인 진척이다.

## 5. 결과 자료

### 먼저 — 한 장씩 찍으려 하지 말 것

**화면 녹화를 켜고 한 번 완주한다.** 실행 중에는 실행에만 집중하고, 끝난 뒤 영상에서 정지화면을 뽑는다.
시연 영상 자체가 제출 서식에 명시된 항목이므로 그대로 결과 자료가 된다.
(윈도우 `Win + G` 또는 PowerPoint 녹화)

### 필수 정지화면 4장

| # | 화면 | 무엇이 보이면 그것인가 | 증명하는 것 |
|---|---|---|---|
| 1 | Agent 1 — 스크리닝 결과 목록 | 이슈가 S01 / S02 / S03 … 쭉 나오고 각각에 판정과 사유가 붙어 있음 | 5~8건을 전부 같은 기준으로 훑었다. **업무 개선 효과 칸의 핵심 주장이며 이를 뒷받침하는 화면은 이것 하나뿐이다** |
| 2 | Agent 2 — 검색이 실제로 일어난 화면 | 조사 질문 목록이 나오는 부분이든 검색 결과가 쌓이는 부분이든 둘 중 하나 | AI가 지어낸 것이 아니라 실제로 자료를 찾았다. 심사에서 반드시 나오는 질문이다 |
| 3 | Agent 2 — 최종 대응안 본문 | `□ 핵심 판단` / `□ (현황) …` / `□ (계획) …` 이 나오는 부분 | **제출 자료의 중심.** 한 화면에 안 들어가면 2~3장으로 나눠 전부 찍는다. 잘린 채로 내지 않는다 |
| 4 | Word로 변환한 문서를 열어놓은 화면 | 변환기로 뽑은 `.docx` 를 실제로 연 모습 | 채팅에서 끝나는 것이 아니라 실제 업무 문서가 나온다 |

### 제출물 구성

- 시연 영상 1개 — 녹화한 전체 실행
- 정지화면 4장 — 위 목록
- Word 문서 파일 1개 — 변환기 출력 (`05_runtime/renderer/`)
- 품질 채점 결과 — Golden Test 채점표 (실행 후 기재)

> **예비 자료** — 인계 데이터 화면, 근거 상태 분포, 추적정보 화면 등은 심사에서 깊은 질문이
> 들어올 때 꺼내는 예비용이다. 녹화해 두면 필요할 때 영상에서 뽑으면 되므로 미리 챙기려 애쓰지 않는다.
