# MRI AI PoC 제출안

_개정: 2026-09-13 / 상태: **설계 검증 완료 · 대체환경 완주 1건 · AIR Studio 등록 실행 대기**_
_초판: 2026-09-12 (구조 검증만 완료) — 웹 버전: https://claude.ai/code/artifact/8842556a-cb89-42b2-a1e8-2b26db1040b2_

사내 제출 서식 5개 칸에 옮겨 쓰기 위한 본문과 결과 자료.
**9-12 초판 대비 가장 큰 변화: 이슈 1건을 처음부터 끝까지 완주했고 산출물이 실제로 존재한다.**
다만 AIR Studio가 아닌 **대체 실행환경**에서 돌렸다. 이 점을 숨기지 않고 서술한다.

## 서술 기조

주된 효과는 속도가 아니다. 현재는 이슈 선별과 조사 범위가 담당자의 착상과 가용 시간에 좌우되고,
조사 근거가 산출물에 남지 않는다. 이 시스템은 전건을 같은 기준으로 훑고, 조사 범위를 고정하며,
확인되지 않은 것을 "없음"이 아니라 "추가 확인사항"으로 남긴다.

시간 단축을 주효과로 내세우면 검수 공수 증가로 반박되므로
**누락 방지 · 근거 추적 · 재현성**을 전면에 둔다.

## 0. 실행 검증 현황 — 먼저 정리할 것

| 구분 | 내용 |
|---|---|
| 무엇을 돌렸나 | MRI '26-제4호 전건 스크리닝 1회 + 선택 이슈 1건(#6 기업 임직원 자산관리 서비스 경쟁 대응) 조사·작성 완주 |
| 어디서 돌렸나 | AIR Studio 접속 불가로 **동일한 프롬프트 정의를 외부 실행환경에서 수동 구동** |
| 지식베이스 | 사내 보유 자료를 동일 구성(정책 10건 / 뉴스 15건 / 제로인 공모 12건 / 협회통계 4건)으로 적재. **외부 웹검색 미사용** |
| 무엇이 같은가 | 처리 단계 정의, 프롬프트 원문, 단계 간 데이터 계약, 출력 양식, 자동 반려 기준 |
| 무엇이 다른가 | 플랫폼 등록·오케스트레이션 실행부. 노드 간 호출을 플랫폼이 아닌 수동으로 연결 |
| 따라서 남은 검증 | **설계의 타당성이 아니라 플랫폼 등록 후의 동작 일치 여부** |

> 이 구분을 먼저 말하면 "안 돌려봤다"가 아니라 "환경 접근만 남았다"가 된다.
> 순서를 바꿔 실행 결과부터 보여주고 나중에 환경을 밝히면 신뢰를 잃는다.

## 1. 업무 개선 효과

### 현행 업무 (AS-IS)

- MRI 1개 호에 주요 이슈 5~8건, 담당 2명이 처리
- 이슈 선별은 담당자가 원문을 읽고 아이디어가 연결되는 주제를 개별 판단으로 선정
- 조사는 인터넷 검색·타사 사례 확인 등 수작업이며, 가용 시간과 검색 결과에 따라 조사 깊이가 달라짐
- 이슈 1건당 대응안 초안까지 약 1일 소요, 한글문서로 작성
- 조사 근거의 출처가 산출물에 남지 않아 사후 확인과 재사용이 어려움

### 개선 후 (TO-BE)

- 호에 포함된 이슈 전건을 동일한 5개 관점(상품·투자테마·고객·채널·그룹협업)으로 스크리닝하고 선별 사유를 기록
- 선택 이슈는 5개 근거 영역(산업·고객 / 정책·제도 / 금융업권·경쟁사 / 자산운용·펀드시장 / 당사 현황)을
  고정 점검하고, 별도 탐색으로 사전에 예상하지 못한 신호까지 수집
- 모든 사실에 출처와 검증상태(확인 / 부분확인 / 추정 / 자료없음)를 부여
- 확인되지 않은 항목을 "없음"으로 단정하지 않고 추가 확인사항으로 분리
- 산출물이 기존 현황 / 계획 양식의 초안으로 즉시 생성되어 담당자가 검수·수정 후 사용

### 실행으로 확인된 결과 (MRI '26-제4호)

| 항목 | 결과 |
|---|---|
| 스크리닝 | 이슈 **7건 전건** 평가 — 검토 착수 가능 1건 / 관찰 3건 / 제외 3건 |
| 선별 근거 | 7건 × 5개 관점 = **35개 평가 전부에 사유 기재** (0점 항목 포함) |
| 조사 실행 | 선택 1건에 대해 검색 **28회** 수행 — 결과확보 23 / 결과없음 4 / 조회오류 1 |
| 근거 정리 | 사실 **36건** — 확인 27 / 부분확인 4 / 추정 3 / 자료없음 2 |
| 산출물 | 현황 5개 영역 전부 작성 · 계획 5개 과제 · **추가 확인사항 9건** 분리 기재 |
| 원문 보존 | 원문 핵심 주제 6개 중 5개 회수, 미회수 1개(3차 개정상법)를 **산출물에 명시** |
| 종합 판정 | 조건부 — 채널 근거 부재를 핵심 판단에 한계로 기재 |

### 기대 효과

| 항목 | 현행 | 개선 후 |
|---|---|---|
| 이슈 검토 범위 | 눈에 띄는 주제 선택적 검토 | 호 내 전건 스크리닝 (7/7 확인) |
| 조사 범위 | 담당자 판단에 의존 | 5개 영역 고정 + 자동 확장 탐색 |
| 근거 추적 | 출처 미기재 | 사실 단위 출처·검증상태 기재 (36건 확인) |
| 미확인 항목 | 조사 중단 시 누락 | 추가 확인사항으로 명시 (9건 확인) |
| 산출물 형태 | 담당자가 처음부터 작성 | 현황/계획 양식 초안 자동 생성 |
| 재현성 | 담당자·시점별 편차 | 동일 기준·동일 절차 적용 |
| 1건 초안 소요 | 약 1일 | AIR Studio 실행 후 측정 |

> 최종 제출물의 판단과 책임은 담당자에게 있으며 산출물은 검수를 전제로 한 초안이다.
> **소요시간은 공란으로 둔다.** 대체환경 실행은 수동 연결·중단 재개가 섞여 있어 측정치로 쓸 수 없다.
> 측정하지 않은 수치를 적는 순간 나머지 수치의 신뢰도까지 함께 떨어진다.

## 2. 운영 적용 가능성

### 현재 구현으로 즉시 적용 가능한 범위

- MRI 전건 스크리닝 및 검토 우선순위 제시
- 선택 이슈의 외부 조사 — 정책·제도, 뉴스·경쟁사, 공모펀드·펀드시장 통계
- 조사 결과를 기존 현황 / 계획 양식의 대응안 초안으로 생성
- 담당자 검수 후 기존 절차대로 제출

### 추가로 필요한 사항

실행 1건으로 **어디가 비는지가 추정이 아니라 관측으로** 확인되었다.

| 항목 | 내용 | 실행에서 드러난 근거 |
|---|---|---|
| 당사 내부자료 연계 | 과거 추진·중단 기획, 상품 파이프라인, 판매채널 전략 | 채널 영역 근거 **없음(NONE)** 판정 — 추가 확인사항 9건의 주된 발생원 |
| ETF 지식베이스 연결 | 당사 ETF 라인업 조회 | 조회오류 1건 발생 — "당사 연금 전용 ETF 보유 여부"가 미확인으로 남음 |
| 펀드 상세지표 매칭 | 상품 목록과 상세 설정액의 식별자 연결 | 목록 3,093건 / 상세 3,261건이나 식별자 교집합 69건에 그침 |
| 부서 의견 반영 | 관련 부서 회신을 근거의 하나로 편입 | 미구현 |
| 다건 일괄 처리 | 선택한 2~3건을 연속 처리 | 현재 1건씩 처리 |
| 운영 절차 정의 | 검수 기준, 책임자, 산출물 보관·이력관리 | 정의 필요 |

### 운영 전제

- AI 산출물은 초안이며 최종 제출물은 담당자 검수 후 확정한다
- 선행조건이 있는 전략은 시스템이 단정하지 않고 검토 대상으로만 제시하며, 실행 판단은 사람이 한다
- 자료없음 항목은 담당자가 보완하거나 추가 확인사항으로 유지한다
- 지식베이스는 정기 갱신이 필요하다

### 환각·과장 방지 장치

생성형 AI의 대표적 위험을 업무 맥락에 맞춰 13종의 자동 반려 기준으로 규정하고
각 처리 단계에 규칙으로 내장했다.

- 근거 없는 수치·기관명·상품명·정책 생성 금지
- 자료없음을 "해당 없음"으로 단정 금지 — 검색 실패와 부재를 구분
- 정책 진행단계 상향 금지 — 논의·검토를 확정·시행으로 표현하지 않음
- 추정을 사실로 전환 금지 — 시기적 일치를 인과관계로 서술하지 않음
- 검증되지 않은 당사·그룹 역량을 보유 사실로 단정 금지
- 작성 단계에서의 신규 전략 창작 금지 — 앞 단계 결과에만 근거
- 상위 근거에 존재하는 정량정보의 임의 축약 금지

### 실행에서 실제로 작동한 사례

규칙이 문서로만 있는 것이 아니라 산출물에서 작동한 흔적이 남았다.

| 규칙 | 실행 산출물에 남은 결과 |
|---|---|
| 자료없음 ≠ 해당 없음 | 채널 근거 부재를 "채널 없음"이 아니라 **"조회된 자료로 확인되지 않음"**으로 기재 |
| 정책 단계 상향 금지 | 기금형 퇴직연금을 **"법률 개정 전 단계"**, 포털 개편을 **"추진 계획 단계"**로 표기 |
| 추정을 사실로 전환 금지 | 주식보상 확대 → 자산관리 수요를 **"개연성 수준으로 해석 가능"**으로 한정 |
| 원문 주제 보존 추적 | 회수하지 못한 주제 1건(3차 개정상법)을 **산출물에 명시** |
| 조사 과제를 계획에 쓰지 않음 | 실행 가능성이 확인되지 않은 전략 2건을 계획에서 빼고 **추가 확인사항으로 이동** |
| 타사 실적을 당사 실적으로 쓰지 않음 | 퇴직연금사업자 적립금을 **"특정 운용사의 상품 판매실적이 아님"**이라고 산출물에 부기 |

> 금융권 업무 적용 시 가장 중요한 평가 요소이므로, 기술 나열보다
> "무엇을 못 하게 막았는가"를 중심으로 서술한다.
> 위 표는 **실제 산출물 문장을 그대로 인용**한 것이므로 근거 요구에 바로 대응된다.

| 근거 정리 | 검색 결과를 영역별로 분류하고 검증상태 부여 | 실행 확인 (36건) |
| 사업기회·전략 도출 | 근거 → 운용사 관점 기회 → 우선순위 전략 → 실행과제 | 실행 확인 |
| 대응안 작성 | 현황 / 계획 양식 초안 및 추적정보 생성 | 실행 확인 |
| 제출 문서 변환 | 최종 산출물을 제출 양식 Word 문서로 변환 | 실행 확인 |
| 품질 자동 판정 | 13종 자동 반려 기준 및 채점 기준 정의 | 기준 수립 · 수동 대조 |
| 당사 내부자료 연계 | 과거 추진 이력·파이프라인·채널 전략 | 미착수 |
| 부서 의견 연계 | 관련 부서 회신 반영 | 미착수 |

### 테스트 결과 — 구조 검증 (완료)

- 워크플로 정의 파일 검증 — 구문 오류 0, 연결 누락 0 (스크리닝 9노드 / 조사 36노드)
- 처리 단계 간 데이터 계약 일치 검증 — 인계 필드 전 항목 일치 확인
- 단계별 출력 규격 중복 정의 해소 — 최종 산출물이 비어 생성되는 결함 사전 제거
- 두 워크플로의 식별자 충돌 제거 — 등록 시 상호 덮어쓰기 위험 해소
- 원문 핵심 주제가 최종 산출물까지 회수되는 경로 확보
- 제출 문서 변환 결과 OOXML 스키마 검증 통과

### 테스트 결과 — 기능 검증 (대체환경 완주 1건)

- 지식베이스 실제 호출 확인 — 검색 28회, 소스별 호출 내역과 인용 원문 발췌를 기록으로 보존
- 최종 산출물 양식 준수 확인 — 4개 블록 구조, 내부용 표기 미노출, 조사 과제의 계획 혼입 없음
- 원문 보존 확인 — 핵심 주제 6개 중 5개 회수, 미회수 1개를 산출물에 명시
- 수치 정합성 확인 — 법인 전용 MMF·TDF 등 산출물 주요 수치를 원자료와 대조
- 자동 반려 기준 13종 수동 대조 — 반려 사유 해당 없음

### 남은 검증 (AIR Studio 등록 후)

- 플랫폼 등록 및 실행 정상 여부
- 플랫폼 지식베이스 연결 시 검색 결과 일치 여부
- 소요시간 측정
- 품질 기준 자동 채점 (합격선 80점 · 자동 반려 0건)

> 구조 검증 + 대체환경 완주까지 완료된 상태임을 명시한다.
> **미완을 숨기면 시연 중 질문 하나로 무너진다.** 남은 것이 설계가 아니라 환경이라는 점이 요지다.

## 5. 결과 자료

### 지금 바로 제출 가능한 것 — 산출물 파일 4종

화면 캡처는 "돌아갔다"를 보이고, 산출물 파일은 "무엇이 나왔다"를 보인다.
**파일은 잘리지도 흐려지지도 않는다. 이쪽이 주 증빙이다.**

| # | 파일 | 내용 | 증명하는 것 |
|---|---|---|---|
| 1 | 스크리닝 검토서 | 이슈 7건 전건 · 관점별 점수와 사유 · 판정 논리 | 전건을 같은 기준으로 훑었다 |
| 2 | 스크리닝 결과 데이터 | 판정·사유가 구조화된 인계 데이터 | 사람이 고른 것이 아니라 기준이 고른 것이다 |
| 3 | 최종 대응안 데이터 | 근거 ID, 검증상태, 원문 주제 회수 현황 포함 | 모든 문장에 근거가 달려 있다 |
| 4 | 대응안 Word 문서 | 현황 / 계획 양식 초안 | 채팅에서 끝나지 않고 업무 문서가 나온다 |

> 보조로 검색 실행 기록(28건의 소스·검색어·결과건수·인용 발췌)을 함께 낼 수 있다.
> "AI가 지어낸 것 아니냐"는 질문이 나오면 이 파일 하나로 끝난다. 심사에서 반드시 나온다.

### 화면 캡처 — AIR Studio 접속 성사 시

AIR Studio는 **대화창에 결과가 그대로 남는다.** 실행이 끝난 뒤 스크롤을 올려 가며 천천히 찍으면 된다.
실시간으로 놓칠 걱정이 없으므로 **화면 녹화는 필요하지 않다.**
제출 서식도 "화면 캡처, 시연 영상, 테스트 결과 **등**"이므로 캡처만으로 충족된다.

**다만 캡처보다 먼저 할 일이 있다.** 실행이 끝나면 대화창 전체를 선택해 복사한 뒤 메모장에 붙여 저장한다.
세션이 닫히거나 초기화되면 되돌릴 수 없고 재실행 비용이 크다. 텍스트를 먼저 확보한 다음 캡처한다.

| # | 화면 | 무엇이 보이면 그것인가 |
|---|---|---|
| 1 | Agent 1 — 스크리닝 결과 | 이슈가 S01 / S02 / S03 … 쭉 나오고 각각에 판정과 사유가 붙어 있음 |
| 2 | Agent 2 — 검색이 실제로 일어난 화면 | 조사 질문 목록 또는 검색 결과가 쌓이는 부분 |
| 3 | Agent 2 — 최종 대응안 본문 | `□ 핵심 판단` / `□ (현황) …` / `□ (계획) …` — 한 화면에 안 들어가면 2~3장으로 나눠 **전부** 찍는다 |
| 4 | Word 변환 문서 | 변환기로 뽑은 `.docx` 를 실제로 연 모습 |

### AIR Studio 접속이 끝내 안 될 경우

**대체환경 실행 화면을 캡처해 제출한다.** 위 4종 파일이 주 증빙이고 캡처는 보조다.
캡처 밑에 한 줄을 반드시 붙인다 — *"AIR Studio 접속 제약으로 동일 정의를 외부 환경에서 실행한 결과"*.
환경을 밝히고 내는 것과 밝히지 않고 내는 것은 심사에서 전혀 다르게 취급된다.

### 제출물 구성

- 산출물 파일 4종 — 스크리닝 검토서 / 스크리닝 데이터 / 최종 대응안 데이터 / Word 문서
- (보조) 검색 실행 기록
- (환경 성사 시) 정지화면 4장
- 품질 채점 결과 — AIR Studio 실행 후 기재

## 예상 질문과 답변

| 질문 | 답변 |
|---|---|
| AIR Studio에서 안 돌린 것 아닌가 | 맞다. 접속 제약으로 동일 정의를 외부 환경에서 구동했다. 프롬프트·데이터 계약·출력 양식은 동일하며, 남은 것은 플랫폼 등록 후 동작 일치 확인이다 |
| 결과를 AI가 지어낸 것 아닌가 | 검색 28회의 소스·검색어·결과건수·인용 발췌가 기록으로 남는다. 사실 36건 각각에 근거 ID와 검증상태가 붙어 있다 |
| 제외 3건은 왜 버렸나 | 5개 관점 각각에 0점 사유가 기재되어 있다. 검토서를 읽고 담당자가 뒤집을 수 있으며, 관찰 등급도 조사 지정이 가능하다 |
| 담당자보다 나은가 | 더 낫다고 주장하지 않는다. 전건을 같은 기준으로 훑고 근거를 남긴다. 판단과 책임은 담당자에게 있다 |
| 시간이 얼마나 줄었나 | 측정하지 않았다. 이번 실행은 수동 연결이 섞여 있어 측정치로 쓸 수 없다. AIR Studio 실행 후 측정해 보고하겠다 |
| 바로 쓸 수 있나 | 당사 내부자료 연계 전까지는 채널·과거 이력 영역이 비며, 이번 실행에서도 해당 항목이 추가 확인사항으로 남았다 |
