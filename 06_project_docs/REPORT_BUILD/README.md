# 결과보고서 서식 도구

에이전트 1·2 결과보고서(콘테스트 제출본)를 만드는 데 쓴 도구다.
**보고서 원고(`agent1.md` · `agent2.md`)와 산출된 `.docx` 는 여기에 없다.**
MRI 이슈 제목과 KB 파일명이 본문에 들어가므로 리포지토리에 올리지 않는다.
원고는 담당자 로컬에 둔다. 여기 있는 것은 그 원고를 사내 양식으로 찍어내는 틀뿐이다.

## `build.js` — 마크다운 → docx

사내 KOR_BDC 양식(레이아웃·표색·글꼴·문단너비)을 그대로 구현한다.

    MD=agent1.md OUT="MRI 이슈 스크리닝 AI 구축 결과.docx" node build.js

`docx` (npm) 하나만 있으면 된다.

### 양식 상수

A4 11906×16838 · 여백 1134 · 본문폭 9638 · 표폭 9217 · `tblInd` 421
나눔바른고딕 Light 13pt · **장평 80%** · 줄간격 259 auto · 양쪽정렬

표는 `columnWidths` 와 셀별 `width` 를 둘 다 DXA 로 준다(구글 문서 호환).
열 너비는 글자 수의 제곱근에 비례시킨 뒤 5–45% 로 잘라 다시 정규화한다.

## `diagram.py` — 구성도 PNG

`fig_agent1.png` · `fig_agent2.png` 는 각 에이전트의 처리 구성,
`fig_map1.png` · `fig_map2.png` 는 두 에이전트의 관계를 보이는 머리 띠다
(현재 문서 쪽이 초록으로 칠해지고 「이 문서」 라벨이 붙는다).

    python3 diagram.py

Pillow 와 나눔바른고딕(`fonts-nanum`)이 필요하다.
생성된 PNG 를 같이 커밋해 두었으므로, 폰트가 없는 환경에서도
`build.js` 는 그대로 돌아간다. 구성이 바뀔 때만 다시 만들면 된다.

## 주의

산출된 `.docx` 를 이 환경에서 렌더해 눈으로 확인할 수단이 없다
(LibreOffice 가 동작하지 않는다). 대신 `word/document.xml` 을 파싱해
표 너비 합(9217)·`tblInd`·그림 개수를 기계적으로 확인했다.
**최종 확인은 워드에서 열어 봐야 한다.**
