# 구현 환경의 제약과 보완 필요사항

원래 설계한 모양과 이번에 구현한 모양이 다른 자리가 있다.
대부분은 판단을 잘못해서가 아니라, **환경이 그 모양을 지원하지 않아 우회한 자리**다.
우회한 자리가 지금 불안정한 파트와 겹친다.

아래는 그 목록이다. 항목마다 셋을 적는다.

    현재     지금 환경이 제공하는 것
    제약     그래서 구현하지 못한 설계
    보완     지원되면 원래 설계대로 구현 가능한 것

---

## Ⅰ. 자료가 들어오는 길

○ **통계 자동 갱신 — 미지원**

- 현재  지식베이스는 담당자가 올린 **시점의 스냅샷**. 올린 뒤에는 그대로 고정
- 제약  · 협회·평가사 통계는 월 단위로 갱신되나, 워크플로는 갱신 사실을 알지 못함
        · 조회 결과의 기준일이 이슈 시점과 어긋나도 워크플로가 스스로 감지하지 못함
        · 실행할 때마다 담당자가 최신 파일을 다시 올려야 함
- 보완  · 자료원 일정 연동(정기 적재) — 월간 통계가 갱신되면 자동 반영
        · 조회 결과에 **기준일 자동 부기**, 기준일이 지난 자료는 실행 중 경고
        · 이슈 시점과 자료 기준일의 간격을 산출물에 명시

○ **외부 공개자료 조회(웹) — 미지원 / 이번 범위 제외**

- 현재  KB에 올린 파일 안에서만 조회. 외부 검색 경로 없음
- 제약  · MRI가 다루는 이슈는 대체로 **최근 사안**이라, 발표 직후 보도자료·감독당국 공지·
          경쟁사 공시가 KB에 없으면 그대로 자료 공백이 됨
        · 공백을 메울 경로가 없으면 그 자리를 **추정으로 채우려는 압력**이 생김.
          이번 구현의 불안정한 파트가 주로 이 자리에서 나옴
- 보완  · **허용 도메인 한정 웹조회**(금융위·금감원·금융투자협회·주요 경제지 등)
        · 조회 결과에 URL·게시일을 규격 필드로 반환 → 담당자가 원문으로 바로 확인
        · 이것이 되면 「자료가 없어 못 쓴 항목」이 「확인된 최신 사실」로 바뀜

○ **사내 시스템 연결 — 미연결**

- 현재  당사 관련 자료는 외부 평가사·협회 자료원으로만 접근
- 제약  · 당사의 **과거 시도(중단·실패 포함)**, **추진 중 파이프라인**, 채널·제휴 현황은
          사내 문서에 있으나 연결된 소스가 없어 산출물에서 빈 칸으로 남음
        · 빈 칸은 「해당 사항 없음」이 아니라 **「연결되지 않음」**이며, 이 구분을
          사람이 매번 확인해야 함
- 보완  · 사내 문서·상품 데이터베이스 커넥터 연결
        · 연결되면 대응안이 「시장에 이런 흐름이 있다」에서
          **「당사는 이미 이것을 해 봤고, 그래서 이렇게 한다」**로 바뀜

○ **자료원 구조(축) 조회 — 미지원**

- 현재  질의를 보내 봐야 자료가 있는지 알 수 있음. 자료원이 가진 축을 미리 물을 수 없음
- 제약  · 집계표·상품 데이터베이스에 없는 축(제도 이름 등)으로 질의가 나가면 답이 없음
        · 답이 없는 질의를 미리 걸러 낼 방법이 워크플로 안에 없음
- 보완  · 자료원 스키마·색인 조회(어떤 구분·어떤 항목·어느 기간이 있는지)
        · 질의 생성 단계에서 **답할 수 있는 질문만** 만들 수 있게 됨

○ **조회 결과의 출처 반환 — 부분적**

- 현재  검색 도구는 문서 목록을 주지 않고 **풀어 쓴 글 한 덩이**를 돌려줌.
        파일명은 글 끝에 꼬리로 붙을 때만 옴
- 제약  · 꼬리가 없는 조회에서는 어떤 문서에서 나온 문장인지 알 수 없음
        · 출처 확인이 **구조적으로 불완전**해지고, 그만큼 사람이 대조해야 함
- 보완  · 도구 응답에 문서 ID·해당 구간·기준일을 **규격 필드**로 반환
        · 반환되면 근거마다 원문 위치가 따라붙어, 확인이 사람 손을 떠남

## Ⅱ. 워크플로를 짜는 길

○ **단계 간 맥락 격리 — 미지원** (이번 구현에서 가장 큰 불안정 요인)

- 현재  앞 단계의 출력이 뒤 단계의 맥락에 그대로 남음. 노드 단위로 끊을 수 없음
- 제약  · 뒤 단계가 자기 일을 하기 전에 **앞 단계의 출력을 본보기로 삼음**.
          앞에서 한 번 어긋나면 뒤로 갈수록 같은 모양이 되풀이됨
        · 단계를 늘려 정교하게 만들수록 이 영향이 커짐 — 설계 의도와 반대로 작동
- 보완  · 노드별 **입력 화이트리스트**(이 노드는 이 필드만 본다)
        · 지원되면 단계를 나눌수록 정확해지는, 원래 의도한 구조가 성립

○ **공유 프롬프트 — 미지원**

- 현재  노드마다 프롬프트를 따로 가짐. 워크플로 공통 규칙을 둘 자리가 없음
- 제약  · 같은 규칙이 노드 수만큼 복사되고, 고칠 때마다 전부를 손봐야 함
        · 실행을 거듭하며 복사본끼리 조금씩 어긋남(드리프트)
        · 이번에는 **외부 생성 스크립트로 우회**(한 골격에서 전 노드를 다시 찍는 방식)
- 보완  · 워크플로 공통 프롬프트 + 노드별 차이만 기술
        · 규칙 한 곳 수정이 전 노드에 반영 → 우회 스크립트 불필요

○ **병렬 분기·합류(fan-in) — 미지원**

- 현재  처리 노드는 입력 하나·출력 하나. 여러 갈래를 한 노드로 합치는 전례 없음
- 제약  · 자료원별 조회를 **동시에 돌리고 한 곳에서 합치는** 정석 구조를 못 씀
        · 자료원 수만큼 **직렬로 길게** 이어야 하고, 체인이 길어질수록 맥락 격리
          문제(위 항목)가 누적됨
- 보완  · 병렬 분기 / 합류 노드
        · 지원되면 자료원이 늘어도 체인 길이가 늘지 않음

○ **반복(루프) — 미지원**

- 현재  노드는 한 번 실행. 배열을 항목마다 돌리는 구조 없음
- 제약  · **「조사 과제 1건 = 1회 실행」**으로 나눌 수 없어, 한 노드가 여러 과제를
          한 번에 처리 → 일부만 처리하거나 비슷한 과제를 합치는 현상
- 보완  · 배열 순회 노드
        · 지원되면 과제 단위로 성공/실패가 남아 어디서 빠졌는지 바로 보임

○ **워크플로 분할·호출 — 불명확**

- 현재  한 워크플로 안에 모든 단계를 넣음
- 제약  · **①조사 설계 ②자료 조회 ③대응안 작성**을 각각 별도 워크플로로 나누어
          단계별로 따로 검증하는 구성을 못 씀
        · 중간 산출물을 사람이 확인하고 넘기는 방식도 수기 복사에 의존
- 보완  · 하위 워크플로 호출
        · 지원되면 조회 결과를 **사람이 검수한 뒤** 작성 단계로 넘기는 운영이 가능

○ **한 노드의 자료원 다중 연결 — 전례 없음**

- 현재  노드 하나에 자료원 하나
- 제약  · 조회를 한 노드로 모으는 단순한 구조를 시험하지 못함
- 보완  · 다중 연결 + 도구 선택 근거 로깅

## Ⅲ. 확인하는 길

○ **실행 로그 격리 — 미지원**

- 현재  도구 호출 줄·오류 메시지가 하류 단계의 맥락에 섞여 들어감
- 제약  · 시스템 메시지를 작업 지시로 받아들이는 경우가 생김
- 보완  · 실행 로그와 단계 간 전달 데이터의 분리

○ **실행 모드별 관측성 차이**

- 현재  실행 모드에 따라 도구 호출 내역이 보이기도, 보이지 않기도 함
- 제약  · 도구 호출 내역이 보이지 않는 모드에서는 **자료를 실제로 조회했는지**
          확인할 방법이 없음. 결과물만 보고는 구분되지 않음
- 보완  · 실행 단위 **구조화 로그**(도구 호출·질의·응답·소요시간) 내려받기
        · 있으면 검증이 사후 대조가 아니라 실행 기록 확인으로 끝남

○ **산출물 자동 검증 — 미지원**

- 현재  노드 출력의 형식·내용을 워크플로 안에서 검사하는 장치 없음
- 제약  · 형식이 어긋난 출력이 조용히 다음 단계로 넘어감
        · 이번에는 **검증 도구를 워크플로 밖에 별도로 구축**해 대응
- 보완  · 노드 출력 스키마 검증 / 후처리 훅
        · 지원되면 검증이 운영 절차가 아니라 워크플로의 일부가 됨

○ **실행 안정성**

- 현재  실행 중 간헐적 시스템 오류 발생(워크플로 설계가 아닌 실행 계층)
- 제약  · 장시간 실행에서 중단 시 처음부터 재실행
- 보완  · 중단 지점 재개, 실패 단계 재시도

## 종합

○ 이번 구현에서 **보완과 검증이 필요한 파트**는 대부분 위 제약을 우회한 자리와 겹침

- 자료 공백이 생기는 자리 → Ⅰ의 자동 갱신·외부 조회·사내 연결 미지원
- 단계가 길어질수록 흔들리는 자리 → Ⅱ의 맥락 격리·병렬 합류 미지원
- 확인에 사람 손이 필요한 자리 → Ⅰ의 출처 반환, Ⅲ의 로그·검증 미지원

○ 우선순위 — 효과가 큰 순서

    1  단계 간 맥락 격리          구현 안정성에 가장 직접적
    2  외부 공개자료 조회          자료 공백 자체를 줄임
    3  통계 자동 갱신 · 기준일 부기  최신성과 시점 정합성
    4  사내 시스템 연결            대응안의 실행 가능성
    5  구조화 로그 · 출력 검증      확인 절차의 자동화

○ 위 항목이 지원되면 **원래 설계한 구조를 그대로 구현 가능**하며,
  현재 우회를 위해 둔 외부 스크립트(프롬프트 생성·산출물 검증)도 불필요해짐
