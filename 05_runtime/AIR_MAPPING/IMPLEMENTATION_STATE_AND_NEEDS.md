# 구현 현황과 보완 필요사항

두 가지를 나누어 적는다. 섞으면 「지금 안 된다」와 「원래 필요하다」가 같은 말처럼 읽힌다.

    Ⅰ. 불안정한 파트    AIR Studio 환경 안에서 이번에 구축한 것의 현재 상태
    Ⅱ. 보완 필요사항    조사 업무에 실제로 쓰이는 에이전트가 되기 위해 필요한 것

Ⅰ은 이번 PoC의 범위 안에서 확인된 사실이고, Ⅱ는 그 범위를 넘어선다.
Ⅰ의 불안정한 자리는 대체로 **환경이 지원하지 않는 모양을 우회한 자리**와 겹친다.

---

# Ⅰ. 불안정한 파트 — 이번 구현의 현재 상태

항목마다 셋을 적는다.

    상태     지금 어떻게 작동하는가
    원인     환경의 어떤 제약에서 비롯됐는가
    대응     현재 어떻게 다루고 있는가

## 1. 자료 조회 구간

- 상태  · 자료원별 조회가 실행마다 고르지 않음. 잘 가져오는 실행과 그렇지 못한 실행이 갈림
        · 조회 결과가 충분치 않은 자리에서 서술이 과하게 확장되는 경향
- 원인  · 처리 단계가 직렬로 길게 이어져 있고, **앞 단계의 출력이 뒤 단계의 맥락에 남음**
        · 단계별 입력을 끊을 수 없어 체인이 길어질수록 영향이 누적
        · 자료원별 병렬 조회 후 합류하는 구조를 쓸 수 없어 직렬로 이은 결과
- 대응  · 조회 전 — 각 조사 과제가 해당 자료원에서 **답할 수 있는 질문인지** 사전 점검
        · 조회 후 — 산출물의 사실 진술을 자료 원문과 **기계 대조**
        · 두 도구 모두 워크플로 밖에 별도 구축. 판정을 모델에 맡기지 않음

## 2. 근거의 출처 표기

- 상태  · 근거마다 출처가 붙는 경우와 「출처미상」으로 남는 경우가 나뉨
        · 출처미상 근거는 **사람이 원문을 찾아 확인해야** 보고서에 쓸 수 있음
- 원인  · 검색 도구가 문서 목록을 주지 않고 풀어 쓴 글을 돌려주며,
          파일명은 글 끝에 꼬리로 붙을 때만 제공됨
- 대응  · 출처가 없는 근거를 버리지 않되 **「검색결과」로 부르지 않음**
        · 「출처미상」으로 표기해 확인이 필요한 근거임을 담당자에게 드러냄

## 3. 자료 공백의 처리

- 상태  · 자료가 없는 항목을 「자료 부족」으로 남기는 것과, 서술로 메우려는 경향이 함께 나타남
- 원인  · KB에 올린 파일 밖을 볼 수 없어, 최근 사안일수록 공백이 구조적으로 발생
        · 공백을 메울 경로가 없는 상태에서 「빈칸을 남기지 않으려는」 압력이 작용
- 대응  · 공백을 **공백으로 보고하는 것이 완수**임을 각 단계 계약에 명시
        · 조회하지 않은 항목과 조회했으나 자료가 없는 항목을 구분해 기록

## 4. 당사 현황 항목

- 상태  · 과거 시도(중단·실패 포함)·추진 중 파이프라인 항목이 빈 칸으로 남음
- 원인  · 사내 문서·상품 데이터베이스가 연결되어 있지 않음
- 대응  · 빈 칸을 「해당 사항 없음」으로 해석하지 않도록 **「내부 소스 미연결」**을 명시
        · 대응안의 실행 가능성 판단은 담당자 몫으로 남김

## 5. 조사 과제 단위의 처리

- 상태  · 한 단계가 여러 조사 과제를 한 번에 다루면서, 일부 과제가 누락되거나 합쳐지는 경우
- 원인  · 배열을 항목마다 도는 반복 구조가 없어 **「과제 1건 = 1회 실행」**으로 나눌 수 없음
- 대응  · 단계마다 실행한 과제와 남은 과제의 장부를 출력하도록 계약
        · 장부가 맞지 않으면 사람이 확인

## 6. 자료의 최신성

- 상태  · 조회 결과의 기준일이 지식베이스에 올린 시점에 고정됨
- 원인  · 자료원 정기 갱신 연동이 없음
- 대응  · 실행 전 담당자가 최신 자료 적재 여부를 확인하는 운영 절차

## 7. 실행 안정성

- 상태  · 장시간 실행에서 간헐적 시스템 오류 발생
- 원인  · 워크플로 설계가 아닌 실행 계층
- 대응  · 재실행. 중단 지점 재개 수단은 없음

# Ⅱ. 보완 필요사항 — 실제 조사 업무에 쓰이려면

이번 구현의 한계를 메우는 것을 넘어, **조사 담당자가 결과를 그대로 쓸 수 있는**
에이전트가 되기 위해 필요한 것들이다. 플랫폼 기능에 한정하지 않는다.

## ① 자료가 늘 최신이어야 한다

- 협회·평가사 통계의 **정기 자동 적재** — 월간 갱신이 사람 손을 거치지 않고 반영
- 조회 결과마다 **기준일 자동 부기**, 이슈 시점과의 간격 표시
- 기준일이 지난 자료로 답할 경우 실행 중 경고
- · 지금은 「올린 시점의 스냅샷」이고, 최신인지는 사람이 기억해야 함

## ② 밖의 자료를 볼 수 있어야 한다

- **허용 도메인 한정 외부 조회** — 감독당국 보도자료·공지, 협회 발표, 주요 경제지, 공시
- 조회 결과에 URL·게시일을 규격 필드로 반환해 원문 확인이 한 번에
- · MRI가 다루는 이슈는 대체로 최근 사안이라, 이것이 없으면 **가장 중요한 자료가 없는 채로**
    조사가 시작됨
- · 이번 PoC는 외부 조회를 범위에서 제외했으나, **실제 운영에서는 이것이 핵심**

## ③ 안의 자료를 볼 수 있어야 한다

- 사내 문서·상품 데이터베이스 연결 — 당사 상품·채널·제휴·파이프라인
- **과거 MRI 대응 이력 자체를 지식베이스로 축적** — 같은 이슈가 다시 오면 그때 무엇을
  답했고 이후 어떻게 됐는지가 근거가 됨
- · 이것이 되면 대응안이 「시장에 이런 흐름이 있다」에서
    **「당사는 이미 이것을 해 봤고, 그래서 이렇게 한다」**로 바뀜
- · 조사 에이전트의 값어치는 대부분 여기서 나옴

## ④ 근거가 원문까지 따라가야 한다

- 검색 도구가 **문서 ID·해당 구간·기준일**을 규격 필드로 반환
- 보고서의 문장에서 원문 위치로 바로 이동
- · 확인이 사람의 대조 작업이 아니라 **클릭 한 번**이 되어야 담당자가 실제로 확인함
- · 확인에 품이 들면 확인하지 않게 되고, 그때 근거의 의미가 사라짐

## ⑤ 검증이 절차가 아니라 기능이어야 한다

- 단계 출력의 **형식 검증**을 워크플로 안에서 수행
- 보고서의 인용이 조회 원문 안에 실제로 있는지 **자동 대조**
- 자료 부족 항목이 서술로 메워지지 않았는지 자동 점검
- · 지금은 검증 도구가 워크플로 밖에 있어 담당자가 따로 돌려야 함
- · 안으로 들어오면 **검증을 통과하지 못한 산출물이 나오지 않음**

## ⑥ 사람이 끼어들 지점이 있어야 한다

- **조회 결과를 담당자가 검수한 뒤** 대응안 작성 단계로 넘기는 구성
- 검수 지점에서 자료 추가·질의 수정·항목 제외가 가능
- · 조사는 한 번에 끝나는 일이 아니라 **묻고 확인하고 다시 묻는 일**
- · 지금은 설계·조회·작성이 한 판에 묶여 있어 중간에 손댈 자리가 없음

## ⑦ 실행이 기록되고 재현되어야 한다

- 실행 단위 **구조화 로그** — 어떤 질의를 보냈고 무엇이 돌아왔고 얼마나 걸렸는지
- 같은 입력에 같은 결과가 나오는지 확인 가능
- 이력 보관 — 언제 어떤 자료로 무엇을 답했는지가 남아야 함
- · 금융회사의 조사 산출물은 **나중에 근거를 되짚을 수 있어야** 함

## ⑧ 품질을 눈으로 볼 수 있어야 한다

- 확정된 정답이 있는 조사 과제 묶음을 만들어 **정기적으로 회귀 시험**
- 프롬프트나 자료를 바꿨을 때 좋아졌는지 나빠졌는지가 즉시 보여야 함
- · 지금은 실행할 때마다 사람이 읽고 판단함. 판단 기준이 실행마다 흔들림

## ⑨ 자료 이용 범위가 정리되어야 한다

- 평가사·협회 자료의 **이용 범위와 반출 가능 범위** 확인
- 사내 자료의 등급별 취급 기준
- · 자동화 범위를 넓히기 전에 정리되어야 할 사항

# 종합

○ 현재 — 환경이 지원하는 범위 안에서 구축하고, **지원하지 않는 부분은 워크플로 밖에서 보완**

- 공통 규칙 관리 · 조회 전 점검 · 조회 후 원문 대조를 별도 도구로 구축
- 불안정한 파트는 대체로 이 우회가 필요했던 자리와 겹침

○ 보완 우선순위 — 조사 에이전트로서의 값어치가 큰 순서

    1  밖의 자료 조회 (②)        자료 공백 자체를 줄임. 실제 운영의 전제
    2  안의 자료 연결 (③)        대응안이 당사 맥락 위에 서게 됨
    3  자료 최신성 (①)           조사 결과의 시점 정합성
    4  근거 추적 · 검증 내재화 (④⑤)  담당자가 결과를 그대로 쓸 수 있게 됨
    5  검수 지점 · 실행 기록 (⑥⑦)   업무 절차로서의 운영 가능성

○ 이번 PoC가 확인한 것 — **조사의 뼈대(이슈 해석 → 조사 설계 → 자료 조회 → 대응안 작성)는
  워크플로로 구성 가능**하며, 남은 것은 위 보완사항을 갖추는 일
